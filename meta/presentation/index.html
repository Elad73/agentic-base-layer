The mental model

Where Agentic Base Layer sits in the stack

Five layers from the brain to your app. Agentic Base Layer is the one you own and reuse.

Agentic Base Layer isn’t code that runs. It is configuration that shapes how the harness behaves — deterministic scaffolding around a non-deterministic model.

Foundations · the harness

The agent loop

An agent is “an LLM using tools based on environmental feedback, in a loop.” The harness is what closes that loop.

🧠

Model

Reasons & decides. Pick the tier per task: Opus for synthesis, Sonnet for volume.

🦾

Harness (Claude Code)

Supplies tools, runs them, feeds results back, manages context & permissions.

🎯

Verification

Tests, linters, gates. “Show evidence rather than asserting success.”

Foundations · context

The context window is a budget

Everything competes for the same finite attention. More tokens ≠ better — accuracy degrades as it fills (“context rot”).

official line target. “Files over 200 lines consume more context and may reduce adherence.”

For each line ask: “Would removing this make Claude make a mistake?” If not — cut it.

A tight, invariants-only CLAUDE.md (~120 lines) is the model shape. The 609-line one is the anti-pattern — move source-of-truth prose to docs/.

The pieces · SKILL

Skills — knowledge that loads itself, just in time

A folder with a SKILL.md. Model-invoked: Claude reads the one-line description and decides when it's relevant. The magic is progressive disclosure.

--- SKILL.md frontmatter --- name: cleanup # ≤64, lowercase-hyphen description: Prune stale # ≤1024 — WHAT + WHEN. artifacts safely. Use when # THE discovery field. cleaning branches/temp files. disable-model-invocation: true # side-effects allowed-tools: Bash Read # skills use allowed-tools

Good description

“Extract text from PDFs, fill forms. Use when working with PDFs, forms, or document extraction.”

Bad description

“Helps with documents.”

Build 3+ evals before writing the skill. One capability per skill. Don't put recurring procedures in CLAUDE.md — make them skills.

The pieces · AGENT

Subagents — a fresh mind in its own context

A flat .md file with a system prompt & scoped tools. It runs in its own context window and cannot see your conversation — that isolation is the whole point.

When to delegate

A task that spans 10+ files, or 3+ independent pieces of work → subagents. Tight, sequential, latency-sensitive work → stay in the main thread.

“Most sub-agent failures aren't execution failures — they're invocation failures. The first invocation must carry everything; there's no mid-run clarification.”

--- the 4-field handoff (~50-100 tokens) --- Task: one or two sentences Files: exact paths (never directories) Context: why this matters / what changed Constraints: perf · security · compat # DON'T dump the whole conversation. # DON'T parallel-write the same file.

The pieces · COMMAND + workflow

Commands drive the task lifecycle

Thin /slash dispatchers: a pre-flight guard → “become the <role> agent” → explicit success criteria. Together they form one disciplined loop.

🔁 Loop Recovery Protocol

Same error 3× → STOP → DOCUMENT → ANALYZE → SIMPLIFY → ALTERNATE → ESCALATE. Stops the model thrashing on a wrong approach — a home-grown pattern worth keeping.

The pieces · HOOK

Hooks — the enforcement layer

Shell commands the harness runs at lifecycle events — deterministic, not probabilistic. This is what CLAUDE.md prose can't do.

⚠ The one gotcha that bites everyone

Only exit code 2 blocks an action. Exit code 1 is treated as a non-blocking error — Claude proceeds anyway. If your hook enforces policy, exit 2.

Good uses

auto-format on editlint/test feedback block rm -rf / .env writessecret scanning desktop/Slack notifyinject session context

Hooks run with your credentials — review any from cloned repos before enabling.

Prompting · the craft

Write at the right altitude

The Goldilocks zone — specific enough to steer, flexible enough to leave room for judgment.

Too low ✗

Hardcoded hex, exact logic, brittle if/else for every case. Breaks the moment reality differs.

Just right ✓

“Color is status, not decoration — keep it under ~5% of a screen.” Strong heuristic + room to act.

Too high ✗

“Make it look nice.” “Handle errors properly.” No grip — the model guesses.

Simple-first

“Find the simplest solution; add complexity only when it demonstrably improves outcomes.”

Evals before optimizing

Start with ~20 real queries + an LLM-judge rubric. You can't improve what you don't measure.

The cheat sheet

Do & Don't, in one place

✓ DO

  • Keep CLAUDE.md < 200 lines; prune ruthlessly
  • One responsibility per skill / agent
  • Trigger-rich descriptions (what and when)
  • Least-privilege tools; reviewers read-only
  • Delegate verbose work to a subagent; keep a summary
  • Pass the 4-field handoff, not the conversation
  • Enforce with hooks/gates (exit 2), not prose
  • Give Claude a pass/fail check to close the loop
  • /clear between unrelated tasks

✗ DON'T

  • Dump 600-line specs into CLAUDE.md
  • Mark everything IMPORTANT (then nothing is)
  • Parallelize agents writing the same file
  • Expect a subagent to ask mid-run — it can't
  • Hardcode absolute paths or stale model names
  • Ship a skill with a vague description
  • Trust exit 1 to block (it won't)
  • Let context fill with stale tool-results
  • Put persona cosplay over portable role names

Your project's CLAUDE.md is the project layer (its invariants, stack, change protocol). Agentic Base Layer supplies the reusable layer beneath it — and steps aside for each project's deliberate overrides.
